Loop de reparo automático

O problema

O Windows tenta corrigir sozinho um erro de inicialização, falha, reinicia e volta para a tela "Preparando Reparo Automático", em um ciclo sem fim.

Possíveis causas

Arquivos de inicialização danificados, como o BCD (Boot Configuration Data, o arquivo que diz ao computador onde está o Windows) ou o MBR (Master Boot Record, o primeiro setor do disco, que inicia o carregamento), o registro do Windows (o banco de dados de configurações do sistema) corrompido ou setores defeituosos no disco.

Solução no Windows

Se a tela de recuperação não aparecer sozinha, ligue o computador e, quando surgir o logotipo do fabricante, segure o botão de energia por 10 segundos; repita duas ou três vezes. Na tela de reparo, vá em Opções avançadas > Solução de problemas > Opções avançadas.

Tente primeiro o Reparo de Inicialização. Se falhar, use a Restauração do Sistema e escolha um ponto de restauração anterior ao problema; ela não apaga arquivos pessoais.

Se os recursos automáticos falharem, abra o Prompt de Comando no mesmo menu e reconstrua a inicialização com bootrec /fixmbr, bootrec /fixboot (se der acesso negado, execute antes bootsect /nt60 sys), bootrec /scanos e bootrec /rebuildbcd. Para verificar o disco, use chkdsk C: /f /r. Como último recurso, Restaurar o PC > Manter meus arquivos reinstala o Windows preservando os documentos.

Solução no Linux

O Linux não tem um reparo automático igual ao do Windows, mas o problema equivalente é o sistema parar no terminal do initramfs (um mini sistema carregado antes do Linux) ou no modo de emergência. Nesse terminal, o comando fsck -y /dev/sda2 (trocando sda2 pela partição do sistema) verifica e corrige o sistema de arquivos; depois, digite exit para continuar a inicialização.

Se o problema for no GRUB, inicie por um pendrive do Ubuntu e use o Boot-Repair, ou monte a partição e execute sudo grub-install /dev/sda e sudo update-grub. Veja também a página Sistema operacional corrompido.
