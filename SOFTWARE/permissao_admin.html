Erro de permissão de administrador

O problema

Ao instalar um programa, apagar um arquivo ou mudar uma configuração, o sistema mostra mensagens como "Você precisa de permissão para executar esta ação", "Acesso negado", "A operação solicitada requer elevação" (Windows) ou "Permission denied" (Linux).

Possíveis causas

A conta usada não tem privilégios de administrador (permissão para alterar o sistema), o programa precisa ser executado com elevação, o arquivo pertence a outro usuário ou ao sistema, ou o computador é de uma escola ou empresa e foi bloqueado de propósito pela equipe de TI.

Solução no Windows

Veja o tipo da sua conta em Configurações > Contas > Suas informações: Administrador ou Conta padrão. Uma conta padrão precisa da senha de um administrador. Em computadores da escola ou do trabalho, o bloqueio é proposital: peça ajuda ao responsável.

Para programas e comandos que pedem permissão, clique com o botão direito e escolha Executar como administrador; isso aciona o UAC (Controle de Conta de Usuário), a janela que pede confirmação. Se o erro for em um arquivo seu, vá em Propriedades > Segurança > Avançado, clique em Alterar ao lado de Proprietário, digite o seu usuário e dê Controle total. Não altere as permissões de pastas do sistema, como C:\Windows.

Solução no Linux

No Linux, o administrador é o usuário root. Comandos que alteram o sistema devem ser executados com sudo na frente (por exemplo, sudo apt install programa), que pede a sua senha. O comando groups mostra se o seu usuário está no grupo sudo; se não estiver, outro administrador pode adicioná-lo com sudo usermod -aG sudo nome-do-usuario.

Para ver as permissões de um arquivo, use ls -l arquivo, que mostra o dono, o grupo e as permissões de leitura (r), escrita (w) e execução (x). Para tomar posse de um arquivo seu, use sudo chown seu-usuario arquivo; para permitir que um script seja executado, use chmod +x script.sh.
